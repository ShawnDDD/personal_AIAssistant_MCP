# 工作助理查询口径

本 skill 只描述「业务口径」：什么话对应哪条流程、参数怎么给、结果怎么判、结论怎么表述。
执行能力在 `web-mcp`（工具 `web_flow_run` / `web_flow_dry_run` / `web_flow_validate`）。

## 意图 → 流程

| 用户表述 | 流程名 | 说明 |
| --- | --- | --- |
| 一对一打卡、一对一补打卡 | `erp_attendance_query` | 「一对一」= 高端配课表 |
| 班课打卡 | 暂未实现（班级配课表） | 未打通前先告知用户 |
| 没说一对一还是班课 | 两条都查 | 当前只有一对一可用，需说明班课缺失 |
| 作业完成情况、作业未完成 | `homework_query` | 按学生姓名单查 |

参数默认值来自本地 `.env`（`ERP_MANAGER`、`TALKWEB_MANAGER`），调用时不用重复传学管。

作业查询额外有 `days`（回看天数）：用户说了时间范围（如「过去六个月」）就传对应天数，改为汇总最近 N 天的全部课程；
用户只给姓名、没提时长时不传，仍按默认逻辑查「未来最近一节课 + 该老师上一次课」。

## 输出格式

- 打卡查询：给出总数 + 未打卡清单（学员、课次时间、课程、教师）；有未打卡时浏览器会自动弹出并保留，提醒用户可手动处理。
- 作业查询：一行结论，形如 `王侠栋｜2026-10-11 雅思中级写作（小班），王家璇 作业未完成`；未布置时形如 `张乐天｜2026-10-24 该次课未布置作业，无作业完成情况`。

## 边界

- 所有流程 `mode: readonly`：不点击打卡、提交、审批类按钮。用户要求代打卡时先说明需改 `mode: mutate` 或传 `allow_dangerous=true`。
- 不展示截图之外的学生信息；只输出被查询学生的结论。
- 登录态过期会返回 `NEED_HUMAN`，此时请用户人工登录后 `web_save_state`。

## 详细口径

- 一对一打卡：`references/erp-attendance.md`
- 作业完成情况：`references/homework-status.md`
