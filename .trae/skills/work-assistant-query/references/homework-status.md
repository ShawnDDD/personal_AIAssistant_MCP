# 作业完成情况查询

流程文件：`flows/homework_query.yaml`（站点 `talkweb`）

## 参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `student` | 是 | 学生姓名 |
| `date` | 否 | 默认 `{{ today }}`，用于推算「未来最近一节课」 |
| `manager` | 否 | 学管姓名，默认读 `.env` 的 `TALKWEB_MANAGER`（固定 `蒋颖`） |
| `days` | 否 | 回看天数。不传（或 0）按默认逻辑取锚点课；传正整数则改为汇总最近 N 天的全部课程，见下文 |

## 查询链路

1. 班级列表页：填学生姓名 + 学管 → 查询 → 结果「操作」列点「班级信息」。
2. 班级信息页点「学情/作业」（新标签页）。
3. 「学情/作业」页点「课中练习」标签。
4. **锚点课**：在课次列表里取上课日期 ≥ 今天 + 1 天中日期最小的一条（即未来最近的一节），记住这一行的**老师**。
   不要求正好是次日；若次日无课，取更靠后的最近一节。
5. **目标课**：同一老师在这节锚点课之前、日期最近的一次课。列表有分页时需翻页汇总后再找。
6. 点该行「学生完成情况」进入课中练习明细页，找到被查询学生那一行。

## 判定规则

| 明细页情况 | 结论 |
| --- | --- |
| 学生行「完成情况」= 未完成 | 输出未完成结论 |
| = 已完成 | 输出已完成结论 |
| 目标单元格为 `--`（该次课未布置作业） | **直接报告「该次课未布置作业」，不再往前找**（用户已确认此口径） |

## 指定回看天数（`days`）

用户明确给出时间范围（如「过去六个月」「近 90 天」）时传 `days`，流程跳过锚点课逻辑，
直接汇总最近 N 天已上过的全部课程：`席乐乐 近180天共 40 节课：未完成 7 次、未布置 33 次`。
未来的排课不计入汇总。只传学生姓名（未提及时长）时不要传 `days`，仍按锚点课那套默认逻辑执行。

## 已结课学生（`fallback_days`）

未来没有任何排课时不报错，改为回看最近 30 天的课程（`flows/homework_query.yaml` 中 `fallback_days: 30`），
覆盖不到再退化为最近 4 节；每节课逐个取状态后汇总成「近 30 天共 N 节：未完成 x、已完成 y、未布置 z」。

- 班课：走课次列表接口取课次，逐个打开明细页读状态。
- VIP 1对1：页面用 `packageCode`、接口不适用，改为逐行点单元格打开明细页读状态。
- 上课时间：从明细页头部文本提取（`13:20-15:20`）。
  **「未布置」的课次不打开明细页，因此该课次时间为空**（已确认不再为此额外取数）。

## 批量连续查询

- 同一个浏览器里连续查多个学生时，流程开头会强制刷新一次（`goto` 的 `reload: true`）：
  单页应用跳到相同地址不会真正加载，不刷新会保留上一位学生的筛选条件和旧表格，可能点到上一次查询的结果。
- 锚点课和「同老师上一次课」优先用课次接口（`lessonList`）算出来，再翻页定位到目标行（找到即停）；
  接口不可用时才退回逐页扫描。定位一步约 0.7 秒，单人整条链路约 15-18 秒。
- 课中练习明细页是点击后新开的标签，读完即关，不会在批量执行时越积越多。
- 身份校验：进入班级详情页后断言页面里出现该学生姓名，最多等 15 秒；
  失败直接报「班级页没有出现学生「X」，可能点到了上一次查询的班级」，不再继续取数。

## 结论格式

```
{老师}｜{上课日期} {课程名}，{学生} 作业未完成
```

示例：
- `王侠栋｜2026-10-11 雅思中级写作（小班），王家璇 作业未完成`
- `张乐天｜2026-10-24 该次课未布置作业，无作业完成情况`

## 交付

- 每次查询都留一张明细页截图，命名 `学生_日期_完成情况.png`，路径随结果返回。
- 未完成时以一句话结论为主，不要堆砌整张表格。
- 结果同时返回锚点课程信息，用于二次确认取的是哪一节课：
  `anchor`（老师｜上课日期，与目标课同一种表达，如 `张力文｜2026-11-22`）、
  `anchor_date`（未来最近一节课日期）、`anchor_teacher`（该课老师）、`anchor_lesson`（总课次）、
  `anchor_time`（该课上课时间）、`row_date`（实际读取的上一次课日期）、`cell_text`（该次课的学生完成情况，如 `2/5`）。
