# 一对一打卡查询

流程文件：`flows/erp_attendance_query.yaml`（站点 `erp`）

## 术语

- 「一对一」= 高端配课表 = 一对一班容的学员打卡情况。
- 「班课」= 班级配课表（尚未打通）。
- 用户未明确时两条都查；当前只能给出了一对一的结果，班课部分要显式说明尚未实现。

## 参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `start_date` | 是 | `YYYY-MM-DD`，服务端存为 `00:00:00` |
| `end_date` | 是 | `YYYY-MM-DD`，服务端存为 `23:59:59`；单日查询时与 start 相同 |
| `manager` | 否 | 学管姓名，默认读 `.env` 的 `ERP_MANAGER` |

「本月」「上周」这类相对时间由调用方换算成具体日期再传，不要依赖页面上的快捷选项。

## 页面行为

1. 日期区间 + 学管 + `学员考勤状态 = 未打卡` 三个条件一起查询，结果集只含未打卡记录。
2. 表格是 ag-Grid 虚拟渲染：横向需滚到最右才渲染学管/打卡状态列，纵向只渲染视口内几行，每页 10 条。抽取逻辑已封装在 `paginate_grid`，不要手工分步模拟。
3. 查询阶段无头执行；命中未打卡时自动切可见浏览器、重放筛选条件、窗口置前并保持打开，等人工处理。
4. 结论里的「总计」应与页面右下角一致，不一致时先怀疑抽取而非业务。

## 交付

- 总数、未打卡明细（学员、课次时间、课程、教师）。
- 全部已打卡时明确说「无未打卡」，不要省略这句。
